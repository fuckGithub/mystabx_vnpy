# 02 数据存储方案

## 1. 结论：三层混合存储（修正"全放 ClickHouse"）

ClickHouse 是列式 OLAP，只适合**追加写 + 分析查询**。交易系统里还有三类它不擅长的数据：高频可变状态、事务型小表、需要唯一约束/外键/UPDATE 的数据。因此采用**按数据特性分层**：

| 层 | 用途 | 引擎 |
|---|---|---|
| **内存态** | 实时行情/委托/成交/持仓/资金（权威实时源） | vnpy MainEngine + EventEngine |
| **时序/分析库** | tick/bar 行情、委托/成交事件、审计、日志 | **ClickHouse（本地）** |
| **事务/配置库** | 用户/账户/会话/策略/设置/告警规则 | **SQLite**（可平滑升级 MySQL/PostgreSQL） |
| **文件存储** | 回测报告、资金曲线、策略代码、配置 JSON | 本地文件系统 |

> 一句话：**实时靠内存，历史靠 ClickHouse，配置与账号靠 SQLite**。

## 2. 数据分类与归属总览

| 数据 | 权威源 | 持久化位置 | 写路径 | 读路径 |
|---|---|---|---|---|
| 实时 tick | 内存 | ClickHouse `tick_data` | 事件驱动异步攒批 | 实时走 WS；历史查库 |
| K 线 bar | 内存/合成 | ClickHouse `bar_data` | DataManager 下载/合成 | 图表、回测查库 |
| 活动委托 | 内存 OMS | 可选快照到 SQLite（崩溃恢复） | 下单 API | REST 读内存 |
| 委托事件流 | 内存 | ClickHouse `order_event` | 事件异步写 | 历史委托查库 |
| 成交事件流 | 内存 | ClickHouse `trade_event` | 事件异步写 | 历史成交查库 |
| 持仓快照 | 内存 OMS | ClickHouse `position_event` | 变更时写快照 | 实时读内存；历史查库 |
| 资金快照 | 内存 OMS | ClickHouse `account_event` | 变更时写快照 | 实时读内存；历史查库 |
| 日志 | EventEngine | ClickHouse `log_event` | 事件异步写 | 实时 WS；历史查库 |
| 审计日志 | 后端 | ClickHouse `audit_log` | 每次操作同步写 | 管理端查库 |
| 用户/账户/会话 | — | SQLite | 管理 API | 认证/鉴权查库 |
| 策略实例/参数 | vnpy CTA 引擎 | SQLite | 策略管理 API | 策略页 |
| 全局设置/连接模板 | vnpy | JSON 文件（`.vntrader`） | 设置 API | 启动加载 |
| 自选/告警规则 | — | SQLite | 前端操作/管理 API | 前端/告警引擎 |
| 回测结果 | — | 文件 + 元数据入 SQLite | 回测完成 | 回测页 |

## 3. 三层架构详解

### 3.1 内存态（权威实时源）
- vnpy `MainEngine` 维护 `orders / trades / positions / accounts / contracts / ticks` 等 dict（OMS 引擎）。
- 前端实时查询一律走内存 + WebSocket，**不查数据库**。
- 数据库只做持久化与历史回看，绝不作为实时链路中间件。

### 3.2 ClickHouse 时序/分析库
- **行情表**：`bar_data`、`tick_data`（量大、纯追加）
- **事件/快照表**：`order_event`、`trade_event`、`position_event`、`account_event`、`log_event`、`audit_log`（append-only 或 ReplacingMergeTree）

### 3.3 事务/配置库（SQLite）
存放可变、需事务、需唯一约束/外键、高频点查的小表：`users / accounts / sessions / strategy_instances / watchlists / alert_rules / backtest_meta`。

### 3.4 文件存储
- 回测结果（资金曲线/回撤/逐笔明细 CSV/JSON）落文件，元数据入 SQLite。
- 策略代码是 Python 文件，放 `strategies/` 目录，不入库。
- 配置 JSON 沿用 vnpy 的 `.vntrader` 约定。

## 4. ClickHouse 表结构（完整 DDL）

字段名**严格对齐 vnpy 4.x 数据对象**，序列化统一 `datetime → DateTime64`、`Enum → String`。

```sql
CREATE DATABASE IF NOT EXISTS vnpy;

-- ============ K线 ============
CREATE TABLE vnpy.bar_data (
    symbol        String,
    exchange      String,
    interval      String,
    datetime      DateTime64(3, 'Asia/Shanghai'),
    open_price    Float64,
    high_price    Float64,
    low_price     Float64,
    close_price   Float64,
    volume        Float64,
    turnover      Float64,
    open_interest Float64
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(datetime)
ORDER BY (symbol, exchange, interval, datetime)
TTL datetime + INTERVAL 5 YEAR;

-- ============ Tick ============
CREATE TABLE vnpy.tick_data (
    symbol        String,
    exchange      String,
    datetime      DateTime64(3, 'Asia/Shanghai'),
    name          String,
    last_price    Float64,
    last_volume   Float64,
    volume        Float64,
    turnover      Float64,
    open_interest Float64,
    open_price    Float64, high_price Float64, low_price Float64,
    pre_close     Float64,
    limit_up      Float64, limit_down Float64,
    bid_price_1   Float64, bid_volume_1 Float64, ask_price_1 Float64, ask_volume_1 Float64,
    bid_price_2   Float64, bid_volume_2 Float64, ask_price_2 Float64, ask_volume_2 Float64,
    bid_price_3   Float64, bid_volume_3 Float64, ask_price_3 Float64, ask_volume_3 Float64,
    bid_price_4   Float64, bid_volume_4 Float64, ask_price_4 Float64, ask_volume_4 Float64,
    bid_price_5   Float64, bid_volume_5 Float64, ask_price_5 Float64, ask_volume_5 Float64
) ENGINE = MergeTree()
PARTITION BY toYYYYMMDD(datetime)
ORDER BY (symbol, exchange, datetime)
TTL datetime + INTERVAL 6 MONTH;

-- ============ 委托事件（append-only）============
CREATE TABLE vnpy.order_event (
    event_time  DateTime64(3, 'Asia/Shanghai'),
    order_id    String,
    gateway     String,
    symbol      String, exchange String,
    type        String, direction String, offset String,
    price       Float64, volume Float64, traded Float64,
    status      String,
    order_time  DateTime64(3, 'Asia/Shanghai'),
    user_id     Int32
) ENGINE = MergeTree()
ORDER BY (event_time, order_id)
TTL event_time + INTERVAL 3 YEAR;

-- ============ 成交流（append-only）============
CREATE TABLE vnpy.trade_event (
    event_time DateTime64(3, 'Asia/Shanghai'),
    trade_id   String, order_id String,
    gateway    String,
    symbol     String, exchange String,
    direction  String, offset String,
    price      Float64, volume Float64,
    trade_time DateTime64(3, 'Asia/Shanghai'),
    user_id    Int32
) ENGINE = MergeTree()
ORDER BY (event_time, trade_id)
TTL event_time + INTERVAL 3 YEAR;

-- ============ 持仓快照（ReplacingMergeTree 去重）============
CREATE TABLE vnpy.position_event (
    event_time DateTime64(3, 'Asia/Shanghai'),
    gateway    String,
    symbol     String, exchange String, direction String,
    volume     Float64, frozen Float64, price Float64,
    pnl        Float64, yd_volume Float64
) ENGINE = ReplacingMergeTree(event_time)
ORDER BY (gateway, symbol, direction);

-- ============ 资金快照（ReplacingMergeTree 去重）============
CREATE TABLE vnpy.account_event (
    event_time DateTime64(3, 'Asia/Shanghai'),
    gateway    String,
    account_id String,
    balance    Float64, frozen Float64, available Float64
) ENGINE = ReplacingMergeTree(event_time)
ORDER BY (gateway, account_id);

-- ============ 日志 ============
CREATE TABLE vnpy.log_event (
    event_time DateTime64(3, 'Asia/Shanghai'),
    level      String,
    source     String,
    message    String
) ENGINE = MergeTree()
ORDER BY event_time
TTL event_time + INTERVAL 1 YEAR;

-- ============ 审计（合规，同步写，不丢）============
CREATE TABLE vnpy.audit_log (
    event_time DateTime64(3, 'Asia/Shanghai'),
    user_id    Int32,
    gateway    String,
    action     String,
    resource   String,
    detail     String,
    ip         String,
    result     String
) ENGINE = MergeTree()
ORDER BY (event_time, user_id)
TTL event_time + INTERVAL 3 YEAR;
```

> 快照表查询用 `SELECT ... FINAL` 或 `argMax(..., event_time)` 取最新状态。

## 5. SQLite 业务库表结构

```sql
PRAGMA journal_mode=WAL;

CREATE TABLE users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    username      TEXT    UNIQUE NOT NULL,
    password_hash TEXT    NOT NULL,
    display_name  TEXT,
    status        INTEGER NOT NULL DEFAULT 1,
    is_admin      INTEGER NOT NULL DEFAULT 0,
    created_at    TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE accounts (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id          INTEGER NOT NULL REFERENCES users(id),
    gateway_name     TEXT    UNIQUE NOT NULL,   -- 'CTP.1'
    gateway_type     TEXT    NOT NULL DEFAULT 'CTP',
    account_name     TEXT,
    connect_settings TEXT    NOT NULL,          -- 加密 JSON
    status           INTEGER NOT NULL DEFAULT 1,
    created_at       TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE sessions (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id       INTEGER NOT NULL REFERENCES users(id),
    refresh_token TEXT    UNIQUE NOT NULL,
    expires_at    TEXT    NOT NULL,
    revoked       INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE strategy_instances (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id        INTEGER NOT NULL REFERENCES users(id),
    gateway_name   TEXT,
    strategy_class TEXT    NOT NULL,
    vt_symbol      TEXT    NOT NULL,
    params         TEXT,
    status         TEXT    NOT NULL DEFAULT 'stopped',
    created_at     TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE watchlists (
    user_id   INTEGER NOT NULL REFERENCES users(id),
    vt_symbol TEXT    NOT NULL,
    PRIMARY KEY (user_id, vt_symbol)
);

CREATE TABLE alert_rules (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id   INTEGER NOT NULL REFERENCES users(id),
    type      TEXT    NOT NULL,
    condition TEXT    NOT NULL,
    channel   TEXT    NOT NULL,
    enabled   INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE backtest_meta (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL REFERENCES users(id),
    params      TEXT    NOT NULL,
    result_path TEXT    NOT NULL,
    created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);
```

## 6. 敏感信息加密（应用层）

```python
from cryptography.fernet import Fernet
import json

KEY = Fernet.generate_key()   # 生产：放环境变量/密钥文件(0600)，不入库不进代码
f = Fernet(KEY)

def encrypt(connect_settings: dict) -> str:
    return f.encrypt(json.dumps(connect_settings).encode()).decode()

def decrypt(ciphertext: str) -> dict:
    return json.loads(f.decrypt(ciphertext.encode()))
```

- 库里存 `encrypt(setting)` 密文；仅连接瞬间 `decrypt` 到内存。
- 密钥轮换 = 重新加密所有 `connect_settings`。

## 7. 与 vnpy 的对接方式

| 场景 | 对接方式 |
|---|---|
| bar/tick 入库/读取（DataManager 下载、ChartWizard 加载、CTA 回测） | 实现 vnpy `BaseDatabase` 接口；官方 `vnpy_clickhouse` 可用则用，否则自定义 `Database` 子类（底层 `clickhouse-connect`） |
| 事件落库（委托/成交/日志/快照） | 桥接层注册 EventEngine 事件，异步攒批写 ClickHouse |
| 用户/权限/设置 | 后端 SQLAlchemy（SQLite）管理，与 vnpy 解耦 |
| 全局设置/连接模板 | 沿用 `.vntrader/*.json` |

## 8. 读写路径、一致性、备份

- **实时路径**：内存 → WebSocket，零库延迟；**历史路径**：查 ClickHouse；**配置路径**：查/写 SQLite。
- **落库不阻塞交易主链路**：异步队列 + 攒批（Buffer 表或批量 insert）。
- **失败处理**：行情允许丢弃；审计/委托事件必须重试 + 告警；审计同步写、不丢。
- **幂等去重**：`order_event` 以 `order_id + status` 追加保留状态机；快照用 `ReplacingMergeTree`。
- **时区统一**：`Asia/Shanghai`，序列化层统一转换。

| 数据 | TTL 保留 | 备份 |
|---|---|---|
| tick | 6 个月 | `clickhouse-backup` 或分区归档 |
| bar | 5 年 | 同上 |
| 委托/成交事件 | 1~3 年 | 冷备 |
| 审计日志 | 3 年 | 冷备 + 可导出 |
| SQLite | 长期 | 每日文件快照 |

## 9. 部署

- ClickHouse：Mac `brew install clickhouse`；或 Docker `clickhouse/clickhouse-server`（端口 9000 native / 8123 http，挂 volume）。
- Python 客户端：`clickhouse-connect`；事务库 SQLAlchemy + SQLite。

## 10. 落地优先级

1. **P0**：内存态实时链路 + SQLite（用户/账户）+ ClickHouse `tick_data`/`bar_data`。
2. **P1**：`order_event`/`trade_event`/`audit_log` 落库 + 历史查询。
3. **P2**：快照表、TTL 与备份脚本。
4. **P3**：回测文件化、告警规则、自选、多租户平滑升级。
