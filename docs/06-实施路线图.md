# 06 实施路线图

## P0 — 目标：跑通「登录 → 连接 → 行情 → 下单/撤单」最小闭环

### 后端

| # | 任务 | 涉及模块 | 完成标准 |
|---|---|---|---|
| B1 | FastAPI 骨架 + 配置 + 日志 | `core/main.py` `config.py` | 启动可访问 `/health` |
| B2 | headless 启动 vnpy 引擎 | `core/engine.py` | 无 Qt 依赖启动 MainEngine + EventEngine，能 `add_gateway(CtpGateway)` |
| B3 | MySQL 初始化（users/accounts/sessions） | `core/db.py` | 建表成功，可插入测试用户 |
| B4 | ClickHouse 建库建表 | `ch_schema.sql` | bar/tick/order/trade/position/account/log/audit 表就绪 |
| B5 | 密码哈希 + JWT 登录/刷新 | `features/auth/api.py` | `POST /api/auth/login` 返回 token |
| B6 | 账户 CRUD + Fernet 加密 | `core/gateways.py` | 新增账户→加密落库→解密连接 |
| B7 | 多 gateway 连接管理 | `core/gateways.py` | 多账户 `CTP.1/CTP.2` 独立 connect/disconnect/状态 |
| B8 | WebSocket 基础设施（鉴权/心跳/订阅） | `core/ws.py` | 连接鉴权、ping/pong、订阅过滤 |
| B9 | 事件转发（EVENT_* → WS） | `core/events.py` | tick/order/trade/position/account/gateway 推到对应账户 |
| B10 | 只读查询接口 | `features/trade/api.py` | `/api/positions|accounts|orders|trades` 按账户过滤 |
| B11 | 下单/撤单接口 | `features/trade/api.py` | `POST /api/orders`、`/orders/cancel` 带归属校验 |

### 前端

| # | 任务 | 涉及模块 | 完成标准 |
|---|---|---|---|
| F1 | Vite + Vue3 + TS + Element Plus + Pinia + Router 骨架 | `ui/` | 空项目能跑，路由可用 |
| F2 | Axios 封装 + token 注入 + 401 处理 | `ui/api.ts` | 自动带 token，401 跳登录 |
| F3 | WebSocket 客户端 + 心跳重连 + 分发 | `ui/ws.ts` | 断线自动重连，消息进 store |
| F4 | 登录页 + 登录态 store + 路由守卫 | `features/auth/LoginView.vue` | 未登录跳登录，登录后进首页 |
| F5 | 默认布局 + 侧栏 + 顶栏（连接状态） | `ui/components/` | 页面骨架 + 导航 |
| F6 | 账户连接管理（列表 + 连接/断开） | `features/admin/` 或顶栏 | 能连/断自己账户，看到状态 |
| F7 | 行情页（合约搜索 + 订阅 + 表格） | `features/market/` | 实时 tick 表格刷新 |
| F8 | 资金/持仓/委托/成交只读页 | `features/account/` `features/trade/` | WS 增量更新，数据正确 |
| F9 | 交易台（盘口 + 下单 + 活动委托） | `features/trade/` | 能下单、能看到活动委托 |
| F10 | 下单二次确认 + 撤单 | `features/trade/OrderTicket.vue` | 下单需确认，撤单生效 |

### 联调与验收（P0 完成标志）

- ✅ 两个不同用户登录，各自连接自己的 CTP 账户，看不到对方资金/持仓/订单。
- ✅ 行情 tick 实时刷新；下单 → 活动委托 → 成交 → 持仓/资金联动更新。
- ✅ 断网后 WS 自动重连，重连后数据补全。
- ✅ 管理员可见全部账户数据。

## P1 — 目标：完整监控 + 历史 + 风控 + 管理

| # | 任务 | 完成标准 |
|---|---|---|
| P1-1 | K 线图（周期切换/缩放/十字光标） | 从 `/api/bars` 加载，点击合约联动 |
| P1-2 | bar/tick 数据下载入库（DataManager 对接 ClickHouse） | 下载的 bar 能进 ClickHouse 并被回测/图表读取 |
| P1-3 | 历史委托/成交查询（ClickHouse） | 按账户+时间+状态分页查询 |
| P1-4 | 日志页（WS 日志流 + 级别过滤） | 实时日志流 + 历史查询 |
| P1-5 | 审计日志（下单/撤单/改参落库 + 管理员查看） | 所有写操作可追溯 |
| P1-6 | 风控开关（最大单量/持仓、二次确认、一键撤单） | 超限拦截，紧急撤单可用 |
| P1-7 | 自选列表 | 保存/加载用户自选合约 |
| P1-8 | 告警规则（成交/亏损/断线 → webhook/邮件） | 触发后收到通知 |
| P1-9 | 管理员后台（用户管理 + 账户管理） | 管理员增删用户、分配账户 |
| P1-10 | 策略管理（CTA）基础版 | 加载类、建实例、启停、参数、状态/持仓/日志 |
| P1-11 | 回测基础版 | 设参数跑回测，展示资金曲线/回撤/统计 |
| P1-12 | 部署脚本（Docker Compose：后端+前端+ClickHouse+Nginx） | 一键起停，局域网可访问。过渡方案：仓库根目录 `./start.sh` 已能单进程托管 API + Vue dist |

> CTA 策略与回测的详细实现阶段（阶段 A–E）见 [09-CTA策略实施规划](09-CTA策略实施规划.md)。
