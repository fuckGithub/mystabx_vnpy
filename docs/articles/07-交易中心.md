## 一、下单链路

```
浏览器填写下单面板 → POST /api/orders → FastAPI 路由
  → 权限校验（gateway 是否可见）
  → 构造 OrderRequest（vnpy 对象）
  → runtime.me.send_order(request, gateway_name)
  → CTP 柜台
  → 回报：EVENT_ORDER / EVENT_TRADE → 桥接 → WS → 前端更新
```

## 二、下单接口：`features/trade/api.py`

```python
class OrderBody(BaseModel):
    gateway_name: str
    symbol: str
    exchange: str
    direction: str      # LONG / SHORT
    offset: str = "OPEN"  # OPEN / CLOSE / CLOSETODAY
    type: str = "LIMIT"   # LIMIT / MARKET
    price: float = 0
    volume: float = Field(gt=0)   # 必须 > 0

@router.post("/api/orders")
def send_order(body: OrderBody, user=Depends(current_user)):
    if body.gateway_name not in visible_gateways(user):
        raise HTTPException(403, "无权限在该账户下单")
    request = OrderRequest(
        symbol=body.symbol,
        exchange=_enum(_EXCHANGE, body.exchange, "exchange"),
        direction=_enum(_DIRECTION, body.direction, "direction"),
        type=_enum(_ORDER_TYPE, body.type, "type"),
        price=body.price, volume=body.volume,
        offset=_enum(_OFFSET, body.offset, "offset"),
        reference=f"web:{user.id}",   # 溯源：谁下的单
    )
    vt_orderid = runtime.me.send_order(request, body.gateway_name)
    if not vt_orderid:
        raise HTTPException(400, "下单失败：网关未连接")
    return {"vt_orderid": vt_orderid}
```

几个要点：

- **枚举容错**：`direction`/`offset`/`type`/`exchange` 都是字符串，后端用一个 `_enum` 容错映射（大小写、`-`/`_` 都兼容）转成 vnpy 枚举；
- **`reference` 溯源**：下单时带上 `web:{user.id}`，审计时能知道是谁下的单；
- **网关未连接**时 `send_order` 返回空 `vt_orderid`，明确报 400。

## 三、撤单

```python
@router.post("/api/orders/cancel")
def cancel_order(body: CancelBody, user=Depends(current_user)):
    order = runtime.oms.get_order(body.vt_orderid)
    if not order or order.gateway_name != body.gateway_name:
        raise HTTPException(404, "委托不存在")
    runtime.me.cancel_order(order.create_cancel_request(), body.gateway_name)
    return {"ok": True}
```

撤单前会**校验委托确实存在、且属于该 gateway**，防止撤错账户的委托。

## 四、只读查询（资金/持仓/委托/成交）

```python
@router.get("/api/positions")  # 持仓
@router.get("/api/orders")     # 委托（active=True 只看活动委托）
@router.get("/api/trades")     # 成交
```

所有只读接口都经过 `_filter(user, items, payload_fn)`，按 `visible_gateways` 过滤后再序列化——隔离与"下单/撤单"同样严格。

## 五、二次确认与风控（前端侧）

下单在**前端**还有一道防线：

- 下单面板提交前弹**二次确认**（方向/价格/手数再核对一遍）；
- 后续可加**风控开关**（单笔最大量、最大持仓、一键撤单 kill switch）。

后端下单本身也有权限校验，所以是"前后端双重把关"。

## 六、事件回推（被动侧）

下单后，前端不是靠轮询，而是靠 WS 收到回报：

- `order` 事件 → 委托状态更新（已报/部分成交/全部成交/已撤）；
- `trade` 事件 → 成交回报；
- `position` / `account` → 持仓、资金联动更新。

这条"主动下单 + 被动回报"的闭环，就是第 3 篇说的双通道机制在交易上的体现。

## 七、小结

- 下单 = 权限校验 → 构造 `OrderRequest` → `send_order`；
- 撤单前校验委托归属；只读接口统一按可见账户过滤；
- 前端二次确认 + 后端权限校验，双保险；
- 回报走 WS 事件，状态实时联动。
