# 日志模块分析文档

## 概述

日志模块负责记录系统中的操作日志和登录日志，位于 `backend/app/plugin/module_system/log/`。通过自定义 FastAPI 路由类 `OperationLogRoute` 自动拦截所有请求，实现日志的自动化采集、查询、删除和导出功能。

---

```
┌─────────────────────────────────────────────────────────────┐
│                    OperationLogRoute                        │
│               (APIRoute 路由装饰器)                           │

└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                    Controller 层                              │
│         GET /list │ GET /detail/{id} │ DELETE /delete │ POST /export
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                    Service 层                                │
│       OperationLogService：业务编排、分页、导出处理              │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                    CRUD 层                                   │
│       OperationLogCRUD(CRUDBase)：数据库增删查                  │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                    Model 层                                  │
│       OperationLogModel：sys_log 表映射                       │
└─────────────────────────────────────────────────────────────┘
```

### 分层职责

| 层次         | 文件                   | 职责                                           |
| ------------ | ---------------------- | ---------------------------------------------- |
| **路由拦截** | `core/router_class.py` | `OperationLogRoute` 自动拦截请求，采集日志信息 |
| **控制器**   | `controller.py`        | 定义 API 端点、权限校验、参数注入              |
| **服务**     | `service.py`           | 业务逻辑编排、分页查询、Excel 导出             |

`get_log_text_column_type()` 函数根据 `DATABASE_TYPE` 配置自动选择列类型：

- **MySQL** → `LONGTEXT`
- **PostgreSQL** → `TEXT`
- **SQLite/其他** → SQLAlchemy `Text`

## API 接口（`controller.py`）

### 路由前缀：`/log`（标签：`日志管理`）

路由类使用 `OperationLogRoute`，所有日志接口会自动触发日志记录（但日志记录自身被排除，防止循环记录）。

| 方法   | 路径           | 说明           | 权限标识                   |
| ------ | -------------- | -------------- | -------------------------- |
| GET    | `/list`        | 分页查询日志   | `module_system:log:query`  |
| GET    | `/detail/{id}` | 日志详情       | `module_system:log:detail` |
| DELETE | `/delete`      | 批量删除日志   | `module_system:log:delete` |
| POST   | `/export`      | 导出日志 Excel | `module_system:log:export` |

### 接口详细说明

#### 1. 查询日志列表 `GET /list`

- **分页参数**：`PaginationQueryParam`（page_no, page_size, order_by）
- **查询参数**：`OperationLogQueryParam`（见下文）
- **默认排序**：按创建时间降序
- **返回**：分页数据（含总数、列表）

#### 2. 日志详情 `GET /detail/{id}`

- **路径参数**：`id`（操作日志 ID）
- **返回**：单条日志完整信息

#### 3. 批量删除 `DELETE /delete`

- **请求体**：`ids`（日志 ID 数组）
- **校验**：ID 列表不能为空

#### 4. 导出 Excel `POST /export`

- **查询参数**：同查询接口
- **返回**：`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 流式文件

## 自动日志采集机制（`core/router_class.py`）

### `OperationLogRoute` 工作原理

`OperationLogRoute` 继承自 FastAPI 的 `APIRoute`，通过重写 `get_route_handler()` 方法实现请求拦截。

**执行流程**：

```
请求进入 → 执行原始路由处理 → 获取响应 → 判断是否记录日志
                                                     │
                    ┌────────────────────────────────┼────────────────────────────┐
                    │ 跳过条件                        │                            │
                    ▼                                ▼                            ▼
          OPERATION_LOG_RECORD=False     方法不在 OPERATION_RECORD_METHOD 中    函数名在 IGNORE_OPERATION_FUNCTION 中
                    │                                │                            │
                    └────────────────────────────────┴────────────────────────────┘
                                                     │
                                             满足记录条件
                                                     │
                                                     ▼
                    ┌─────────────────────────────────────────────────────────────┐
                    │                    采集日志信息                               │
                    │  1. 解析 User-Agent → OS + Browser                         │
                    │  2. 解析请求体 → JSON/FormData                              │
                    │  3. 获取请求 IP → X-Forwarded-For / client.host             │
                    │  4. IP 地理定位                                              │
                    │  5. 计算处理时间                                              │
                    │  6. 区分日志类型：登录(1) / 操作(2)                           │
                    │  7. 查询操作人账号/手机号（从 UserModel 查询）                │
                    │  8. 获取登录平台（从 JWT scope.login_type 获取）              │
                    │  9. SM2 签名（完整性保护）                                    │
                    └─────────────────────────────────────────────────────────────┘
                                                     │
                                                     ▼
                    ┌─────────────────────────────────────────────────────────────┐
                    │                    异步入库                                   │
                    │   async_db_session → OperationLogService.create_log_service  │
                    └─────────────────────────────────────────────────────────────┘
```

### 关键配置项

配置项在 `settings.py` 中定义：

| 配置                        | 默认值                               | 说明                                         |
| --------------------------- | ------------------------------------ | -------------------------------------------- |
| `OPERATION_LOG_RECORD`      | `True`                               | 全局开关，是否记录操作日志                   |
| `OPERATION_RECORD_METHOD`   | `{"POST", "PUT", "DELETE", "PATCH"}` | 需要记录日志的 HTTP 方法                     |
| `IGNORE_OPERATION_FUNCTION` | 包含 `get_obj_list_controller` 等    | 忽略记录的接口函数名，防止日志接口自身被记录 |

### 日志过滤逻辑

1. **全局开关**：`OPERATION_LOG_RECORD=False` 则不记录
2. **方法过滤**：仅记录 `OPERATION_RECORD_METHOD` 中的方法
3. **函数白名单**：`IGNORE_OPERATION_FUNCTION` 中的函数不记录
4. **文档过滤**：来自 Swagger/Redoc 文档的请求不记录
5. **请求体优化**：超过 2000 字符的 payload 截断为"请求参数过长"

### SM2 日志签名

日志采集时，对 `request_payload | response_json | process_time` 三个字段使用 SM2 算法签名，将签名值和被签名字段标识存入数据库，实现日志完整性保护，防止日志被篡改。

## 服务层（`service.py`）

### `OperationLogService` 方法列表

| 方法                                                               | 作用                   |
| ------------------------------------------------------------------ | ---------------------- |
| `get_log_detail_service(auth, id)`                                 | 获取单条日志详情       |
| `get_log_list_service(auth, search, order_by)`                     | 获取日志列表（不分页） |
| `get_log_page_service(auth, page_no, page_size, search, order_by)` | 分页查询日志           |
| `create_log_service(auth, data)`                                   | 创建日志记录           |
| `delete_log_service(auth, ids)`                                    | 批量删除日志           |
| `export_log_list_service(operation_log_list)`                      | 导出日志到 Excel       |

### 分页查询

`get_log_page_service` 使用传统 `OFFSET/LIMIT` 分页，依赖 `CRUDBase.page()` 方法，支持自定义排序和条件查询，返回结果包含总条数和当前页数据。

### Excel 导出

`export_log_list_service` 使用 `ExcelUtil.export_list2excel()`（基于 `pandas` + `openpyxl`），字段映射如下：

| 英文字段          | 中文表头                      |
| ----------------- | ----------------------------- |
| `id`              | 编号                          |
| `username`        | 操作账号                      |
| `mobile`          | 手机号                        |
| `login_platform`  | 登录平台                      |
| `type`            | 日志类型（登录日志/操作日志） |
| `request_path`    | 请求URL                       |
| `request_method`  | 请求方式                      |
| `request_payload` | 请求参数                      |
| `request_ip`      | 操作地址                      |
| `login_location`  | 登录位置                      |
| `request_os`      | 操作系统                      |
| `request_browser` | 浏览器                        |
| `response_json`   | 返回参数                      |
| `response_code`   | 相应状态（成功/失败）         |
| `process_time`    | 处理时间                      |
| `description`     | 备注                          |
| `created_time`    | 创建时间                      |
| `updated_time`    | 更新时间                      |
| `created_id`      | 创建者ID                      |
| `updated_id`      | 更新者ID                      |

## 菜单与权限

日志管理在系统菜单中的位置：

```
系统管理
  └── 日志管理             route: /system/log
       ├── 查询日志         module_system:log:query
       ├── 日志详情         module_system:log:detail
       ├── 日志删除         module_system:log:delete
       └── 日志导出         module_system:log:export
```

所有接口均使用 `AuthPermission` 依赖注入进行权限校验，未授权的请求被自动拒绝。

## 数据流示例（以创建操作为例）

```
用户请求 PUT /api/v1/system/user/1
       │
       ▼
OperationLogRoute.custom_route_handler()
       │
       ├── 1. 执行原始请求（更新用户）
       │
       ├── 2. 响应返回后，判断是否记录日志
       │      ├── PUT 在 OPERATION_RECORD_METHOD 中 → 继续
       │      └── 函数名不在 IGNORE_OPERATION_FUNCTION 中 → 继续
       │
       ├── 3. 采集日志信息
       │      ├── User-Agent → OS: macOS, Browser: Chrome
       │      ├── X-Forwarded-For → IP: 192.168.1.100
       │      ├── IP 定位 → 登录位置: 广东省深圳市
       │      ├── 耗时计算 → 0.23s
       │      ├── 用户 ID → scope.user_id = 1
       │      ├── 日志类型 → 2（操作日志）
       │      ├── 查询用户 → username='admin', mobile='13800138000'
       │      ├── 登录平台 → scope.login_type = 'PC'
       │      └── SM2 签名 → signature = "xxxx"
       │
       └── 4. 异步写入数据库
              └── INSERT INTO sys_log (type, request_path, ..., username, mobile, login_platform, signature)
                   VALUES (2, '/api/v1/system/user/1', ..., 'admin', '13800138000', 'PC', 'xxxx')
```
