# Flutter 布局规范（强制）

> 全项目 Flutter 布局统一规范（2026-08 沉淀：RenderFlex 溢出修复 P0-P3 + 全库固定高容器审计 + 认证页内联文本范式；
> 2026-09 增补：§10 状态栏图标亮度声明、§14 水平滚动容器与 iOS 侧滑返回手势冲突）。
> 本文档由 `AGENTS.md` 引用（§布局规范），写新页面/改共享组件**前先过一遍本规范**（见 §13 检查清单）。
> ⚠️ 主题 token 一律使用本项目 `DesignColors` / `DesignSize` / `DesignTextStyle`（配合 screenutil `.w`/`.h`/`.r`/`.sp`），**禁止**使用其他项目的 `AppColors` / `AppSpacing`。
> 核心原则：**让内容决定尺寸，只在内容确实固定时才固定尺寸**；动态内容进 Flex 一律可约束 + 省略；内联文本用富文本整段排版。

## 0. 溢出根因与修复优先级

- 根因：**内容固有尺寸 > 容器约束尺寸**（固定高 / 非弹性 Flex / 无约束 `Text`）→ `RenderFlex overflow` 断言
- 修复优先级：**① 取消固定高让内容自适应 > ② 调大高度 > ③ 内部滚动**
- 诊断：看报错定位 `Column`/`Row` 行号 + 溢出方向（`Axis.vertical`/`Axis.horizontal`）+ 像素数，判断是谁的内容在超
- 常见根因链：固定高容器 → 内部动态文本/多行输入/等比网格 → 换行/变宽/放大后超出

## 1. 内联文本流（协议行/富文本拼接）— 用 `Row` + `Flexible` + `Text.rich`，禁止 `Wrap`

- 场景：多段文字 + 可点链接拼接（协议行「已阅读并同意**用户协议、隐私政策**」、前缀 + 链接 + 分隔符、标签串）
- ❌ **禁止用 `Wrap` 承载内联文本**：`Wrap` 对每个 `Text`/`TextButton` **逐子测量**，组合宽度一超可用宽度即断行 → **首行未填满就提前换行**（注册页协议行曾踩坑，视觉上「没占满宽就换行」）
- ✅ **`Row` + `Flexible` + `Text.rich`**：整段作为**单一段落**排版，填满整行宽度才换行；窄屏/Web 下 `Flexible` 约束到剩余宽度，超宽自然换行而非溢出
- ✅ 链接用 `TextSpan(recognizer: TapGestureRecognizer())`，**禁止 `TextButton` 拼行**（自带高度/内边距会撑破行高）

```dart
Row(
  crossAxisAlignment: CrossAxisAlignment.center,
  children: [
    TDCheckbox(checked: _agreeProtocol, ...),
    const SizedBox(width: DesignSize.spaceSm),
    Flexible(child: _buildCertText()),
  ],
)

Widget _buildCertText() {
  const plainStyle = DesignTextStyle.bodyLg; // fontSize 16
  const linkStyle = TextStyle(fontSize: 16.sp, color: DesignColors.primary);
  return Text.rich(
    TextSpan(
      style: plainStyle,
      children: [
        const TextSpan(text: '已阅读并同意'),
        TextSpan(
          text: '《用户协议》',
          style: linkStyle,
          recognizer: TapGestureRecognizer()
            ..onTap = () => _showAgreement('user'),
        ),
        const TextSpan(text: ' 和 '),
        TextSpan(
          text: '《隐私政策》',
          style: linkStyle,
          recognizer: TapGestureRecognizer()
            ..onTap = () => _showAgreement('privacy'),
        ),
      ],
    ),
  );
}
```

适用：登录/注册等协议行按此范式（当前项目暂无以 `Text.rich` 拼装的现成范本，新代码遵循）

## 2. `Wrap` 合法用途 — 固定尺寸 item 流

- ✅ `Wrap` 仅用于**固定/近固定尺寸的 item 横向流**（换行是主动设计，不涉及文字整段排版）：
  - **图片网格**：固定尺寸项（头像/商品图，`spacing`/`runSpacing`）
  - **筛选 chips**：固定尺寸标签流（`Wrap(spacing: DesignSize.spaceSm)`）
- 判定口诀：**凡涉及文字整段排版 → §1 `Row` + `Flexible` + `Text.rich`；凡固定尺寸 item 流 → `Wrap` 保留**

## 3. `TDCell`（TDesign）右侧长文本 — 必须约束，禁止裸 Text

- TDCell 内部右侧是**非弹性 `Wrap`**，`rightIconWidget` 传长 `Text` 无任何约束会溢出（测试与窄屏必现）
- ✅ 长右值（脱敏证号/电话/审核备注等）统一用 `ConstrainedBox(maxWidth: 屏宽-预留) + Text(maxLines: 1, overflow: TextOverflow.ellipsis)` 兜底
- ✅ 推荐封装统一的行组件（如 `AppInfoRow`），内部已做 `ConstrainedBox` + 单行省略，避免每处手动处理
- ❌ 禁止把动态长 `Text` 直接塞进 `rightIconWidget`

## 4. 手写 `Row` 中动态文本 — 必须 `Flexible` + `maxLines:1` + ellipsis

凡是文本来自 **API 返回/用户输入/可增长的参数**，进 `Row` 必须：

- ✅ 用 `Flexible(child: Text(..., maxLines: 1, overflow: TextOverflow.ellipsis))` 包裹
- ❌ 禁止裸 `Text` 与 `Spacer`/`spaceBetween` 共存（左侧标题会被挤溢出）；`spaceBetween` 行的右侧 value 用 `Flexible` + `textAlign: TextAlign.right`
- ❌ 禁止 `Row(mainAxisSize: MainAxisSize.min)` 内放长文本（会随文本撑出屏幕）——去掉 `min` 并用 `Flexible` 包裹

适用：列表/详情行的标题、右侧 value、动态文案一律按此范式（`mine_tab.dart` 用户名行、`work_list_page.dart` 列表项等动态文本进 `Row` 时逐一检查）。

### §4 补充 — `[Expanded 弹性主体 + 非弹性右侧项]` 陷阱

- 金额/徽标这类**受控文本**可保持非弹性贴右，但**勿随手套 `Flexible`** —— `Flexible(flex: 1)` 会与左侧 `Expanded` **1:1 平分剩余**、右侧占半宽、左侧主体被无谓压缩（`extra_fee_card` 已核实，非万能解）
- 🔴 **自由文本（API/用户输入）绝不放非弹性位**

## 5. 非必要不固定高度（强制）

内容会随输入/加载/数据变化的区域，**不要用固定高度**（`SizedBox(height:)` / `Container(height:)` 包动态内容），否则内容超出即 `RenderFlex overflow`：

- ✅ **多行输入**（反馈/评价等）用 `TDTextarea` 的 `minLines`/`maxLines` 内容自适应
  （初始行数用 `minLines`，`maxLines: null` 长内容自动增高；**禁止**再包 `SizedBox(height: 96)` 等固定高）
- ✅ **动态文本/列表/网格**：用 `minLines`/`maxLines`、`ListView`/`GridView` 内容撑高或 `shrinkWrap`，让高度随内容走
- ✅ 只有**真正需要固定高**的场景才保留（导航栏、按钮、固定栏、对齐 Android 的等高管如图片网格）
- ❌ 禁止「固定高容器 + 内部自适应组件」组合（如 `SizedBox(height: 96) + TDTextarea` → 必然溢出）
- ⚠️ **等比网格是隐蔽溢出源**：`GridView(childAspectRatio: 1)` 单元高 = 单元宽，宽屏（430dp 等）单元宽 > 固定高即溢出 → 固定高外去 `SizedBox` 改用 `shrinkWrap: true` 让网格撑高
- 溢出修护优先：**取消固定高让内容自适应** > 调大高度 > 内部滚动

适用：`feedback_page.dart` 反馈输入等**多行输入一律用 `TDTextarea.minLines`/`maxLines` 自适应，禁止包固定高**；动态列表/网格用内容撑高或 `shrinkWrap`。

## 6. 固定行/固定高容器内动态文本 — 必须单行省略

`SizedBox(height: 44/72)` 等固定行 + 动态 `Text`（API 返回的企业名/金额/状态等）**必须** `maxLines: 1` + `TextOverflow.ellipsis`，否则换行即溢出固定行：

- ✅ `Text(value, maxLines: 1, overflow: TextOverflow.ellipsis, ...)`
- ⚠️ 已有 `Expanded`/`Flexible` 包裹 ≠ 已防溢出——`Expanded` 只限宽不限高，长文本仍会换行撑高固定行
- ⚠️ 统计行（如 72dp 高的金额/数量显示）同样适用，长金额文本也需单行省略

适用：固定行高列表项 + 动态值（`work_list_page.dart` 等）一律 `maxLines: 1` + `TextOverflow.ellipsis`；详情卡片的信息行同理。

## 7. 固定高 `TextField` 文字偏上 — 先查是否被容器挤压

固定高输入框内文字/占位**偏上**（Android 常见）时，**先查 `TextField` 是否被容器 padding 双重内缩挤压到低于固有高度**：

- 容器 `padding: vertical 8` + `TextField.contentPadding: vertical 8` = 16dp，而 16px 文字行高 ~22dp 放不下 → 文字溢出贴顶，`textAlignVertical.center` 无法居中
- ✅ 去掉容器内层 padding 让 `TextField` 占满容器高，`contentPadding` 给足（内容区 > 行高），`textAlignVertical: center` 才能真正居中
- 通用经验：**先保证 TextField 未被挤压到低于固有高度，再谈对齐**

已修复范本：搜索框 `AppSearchBox`（去掉容器 `padding: vertical 8` + `contentPadding` 改 `s12`）。

## 8. `Tab` 自定义内容必须显式 `height`（Flutter SDK 约束）

- Flutter `Tab` **不按内容自适应高度**（SDK `tabs.dart` 实证）：`height: null` 时内置 `_kTabHeight=46`（无 icon）/ `_kTextAndIconTabHeight=72`（icon+text）
- 自绘图标+文字（红点角标 + per-tab 选中色）用**内置 `icon:` + `child:` 组合**：icon 传 `Stack`（图+角标，`Clip.none`），child 传自定义色 `Text`（`text:` 只能走 TabBar 单一 `labelColor`，做不了 per-tab 色）→ 高度自动 72、内部居中、无溢出
- ❌ 自绘内容**不要去掉 `height`**（会塌到 46 溢出 ~27px）；也不要裸 `Column(40 图标行 + text)` 手拼（易 1px 溢出）

已修复范本：首页 4 Tab（`Tab(icon: Stack(图标+红点), child: Text(per-tab 色))`）。

适用：自定义 Tab 内容一律显式 `height` 或用内置 `icon:` + `child:` 组合（主框架/工作台 Tab 若自绘图标+文字按此范式）。

## 9. 移除固定高包装后必查残留括号

把 `SizedBox(height: X, child: Widget)` 改为 `Widget` 直挂父级时，**原 `SizedBox` 的闭合 `),` 会残留** → 语法错/结构错（移除固定高包装后常踩）。改后立即 `flutter analyze` 并检查闭合括号。

## 10. 自绘导航栏/底部栏 — 必须状态栏安全区

自绘 `PreferredSize` 导航栏/底部栏**必须叠加 `MediaQuery.paddingOf(context).top/bottom`**（参考 `TDNavBar`：`paddingTop = MediaQuery.paddingOf(context).top`），否则内容贴顶被状态栏遮挡：

- ✅ `height: MediaQuery.paddingOf(context).top + 内容高`；`preferredSize` **同步含 paddingTop**（否则 body 与导航栏重叠）
- Web 端 `padding.top = 0`（无回归）

已修复范本：搜索导航栏等自绘 AppBar。

适用：自绘导航栏/底部栏（搜索导航等）一律叠加 `MediaQuery.paddingOf(context).top/bottom` 安全区。

- 🔴 **状态栏图标亮度声明（2026-09-09）**：导航栏/顶部视觉必须声明状态栏图标亮度与背景匹配——
  白底→深色图标、深底/彩底→浅色图标，统一走 `AnnotatedRegion<SystemUiOverlayStyle>`：
  - 标准导航栏：已按 `background` 亮度**自动推断** `statusBarIconBrightness`（可显式覆盖）+ `statusBarColor: transparent`；页面**勿再手写 `SystemChrome` 覆盖**（会残留/冲突）
  - 橙/渐变头页：显式 `Brightness.light`（白字）
  - Android 深色系统模式坑：`values-night/styles.xml` `NormalTheme` parent 必须 `Theme.Light` + `statusBarColor transparent`，**勿用 `Theme.Black`**——否则深色系统下状态栏黑底 + 页面深色图标 → 时间等看不清（App 恒 `themeMode.light`）

## 11. 静态短文案豁免

静态短文案/固定常量、长度受控的状态枚举短词**无需**包裹——长度固定不会溢出，包裹反而增加无谓嵌套。

### §11 补充 — 豁免自证边界

- 豁免需自证：仅**格式受控**（`toStringAsFixed` 且业务有上限）或**取值受控**（后端枚举字典徽标）才可非弹性
- 此类项窄屏测试给**现实极值**（如 ¥9,999,999.99），勿用业务不可能的超长串制造伪失败
- 🔴 不得因「看着短」豁免订单号/公司名/地址等自由文本

## 12. 测试字体会放大溢出（Ahem）

widget 测试环境用 Ahem 字体（**每个字形宽 = fontSize**），字形比真机宽得多，320/375 窄屏下更容易触发溢出——这是**特性不是缺陷**：新布局务必用 `tester.pumpWidget` 窄屏冒烟 + `expect(tester.takeException(), isNull)` 提前暴露潜在溢出点。

### §12 补充 — Ahem 窄屏冒烟实战案例

- 记录 `extra_fee_card_layout_test.dart` 实证：Ahem 窄屏三连（320 常规 / 320 极端 / 280 超窄）**首跑即命中两个真实残留溢出**（金额行、徽标行两处非弹性受控项边界）
- 结论沉淀：**给 `Row` 加完 `Flexible`/`maxLines` 后务必再补窄屏极端用例**，专打「看似已加省略、实则非弹性项残余边界」
- 测试数据设计准则：**自由文本给极端长**覆盖省略路径 / **受控文本给现实极值**

## 13. 写新页面/组件前检查清单

1. 内联文本流（协议行/富文本）：`Row` + `Flexible` + `Text.rich`，未用 `Wrap` 拼行？
2. 多行输入：用 `TDTextarea.minLines/maxLines`，未包固定高？
3. 动态文本进 `Row`：`Flexible` + `maxLines:1` + ellipsis？
4. 固定行（44/72 等）+ 动态值：单行省略？
5. 动态列表/网格：内容撑高或 `shrinkWrap`，未包固定高？
6. 固定高输入框：未被容器 padding 挤压到低于固有高度？
7. `Tab` 自绘内容：显式 `height` 或内置 `icon+child`？
8. 自绘导航/底部栏：状态栏安全区？
9. 顶部视觉（导航栏/橙头页）已声明状态栏图标亮度与背景匹配（白底深/深底浅），未手写 SystemChrome 覆盖？
10. 主 Tab 页水平滚动容器（`TabBarView`/`PageView`）：已 `NeverScrollableScrollPhysics()`（§14）？
11. 收尾：`flutter analyze` 0 error + 新布局窄屏 widget 冒烟？

## 14. 水平滚动容器必须禁用手势（iOS 侧滑返回冲突）

**主 Tab 页**（`StatefulShellRoute` branch 内）的水平滚动容器会与 iOS 原生侧滑返回在 **gesture arena** 竞争并**吞掉侧滑手势** —— 表现：全 App 侧滑返回在 Tab 页全失效。

- ❌ 症状：iOS 上从 Tab 页 push 的子页（运单详情等）**两侧边缘侧滑都无反应**；去掉 Tab 页的水平滚动即恢复
- ✅ 修复：主 Tab 页的 `TabBarView` / `PageView` 一律 `physics: const NeverScrollableScrollPhysics()`

  ```dart
  TabBarView(
    controller: _tabController,
    physics: const NeverScrollableScrollPhysics(), // 避免吞掉 iOS 侧滑返回
    children: [...],
  ),
  ```

- **设计取舍**：Tab 切换仅靠顶部 TabBar 点击（**对齐 Android 原生**，Android 原本也不支持左右滑切 Tab）→ 禁用后行为更贴近原生，不是功能损失
- **仅限主 Tab 页**：栈底页（`/login` `/guide`，`go` 进入无法 `pop`，无侧滑可冲突）与 Tab 页**内部** push 的子页（如登录页密码/验证码 `PageView`）保持默认 `physics` 不受影响
- **配套**：路由层 `GoRoute` 需用 `pageBuilder` + `adaptivePage()`（iOS `CupertinoPage` 才有侧滑手势），详见 `AGENTS.md`「路由与启动流程」
