# 环境与版本控制

> 本文档说明本项目的**环境切换机制**与 **Android / iOS 版本号自动推导**。版本号单一来源为 `lib/env/.env.<ENV>` 文件，构建时只需指定 `ENV`，无需手工传 `--build-name/--build-number`。

## 一、环境选择机制

构建 / 运行时通过 `--dart-define=ENV=xxx` 指定环境，代码在 `lib/env/index.dart` 的 `AppEnv.init()` 中按 `ENV` 加载对应 `.env` 文件：

```dart
const String env = String.fromEnvironment('ENV', defaultValue: 'dev');
const String fileName = 'lib/env/.env.$env';
```

| ENV 值 | 环境文件            | API 地址                       | 用途            |
| ------ | ------------------- | ------------------------------ | --------------- |
| `dev`  | `lib/env/.env.dev`  | `http://192.168.1.225:6100`    | 开发 / 本地调试 |
| `test` | `lib/env/.env.test` | `https://test-api.example.com` | 预发布 API      |
| `prod` | `lib/env/.env.prod` | `https://api.example.com`      | 生产 API        |

> ⚠️ 上表 `test` / `prod` 的 `API_BASE_URL` 为占位示例，按实际部署环境替换即可；`dev` 默认 `http://127.0.0.1:6100`（Web 快速开发），连真机时改为局域网 IP。
> ⚠️ 加载失败时回退 `.env.dev`（`AppEnv.init()` 的兜底逻辑）。

## 二、版本号单一来源（.env 文件）

每个 `.env.<ENV>` 文件中的字段决定 **Android APK 的版本**：

| 字段          | 对应          | 说明                                                                      |
| ------------- | ------------- | ------------------------------------------------------------------------- |
| `APP_NAME`    | 应用名        | 展示用名称（`AppEnv.appName` 读取）                                       |
| `APP_VERSION` | `versionName` | 展示版本号（同时被 `AppEnv.appVersion` 读取，用于「关于 → 版本号」toast） |
| `APP_BUILD`   | `versionCode` | Android 整数版本号，**必须大于已安装版本**才能覆盖安装                    |

示例（`.env.dev`）：

```dotenv
ENV=dev
API_BASE_URL=http://192.168.1.225:6100

APP_NAME=FastapiAdmin
APP_VERSION=3.0.0-alpha
APP_BUILD=301
```

### Gradle 自动推导原理

`flutter build` 会把 `--dart-define` 以 base64 编码拼成 `-Pdart-defines=...` 传给 Gradle。
`android/app/build.gradle.kts` 在配置阶段：

1. 解码 `dart-defines` 取出 `ENV` 值；
2. 读取 `lib/env/.env.<ENV>` 中的 `APP_VERSION` / `APP_BUILD`；
3. 写入 `defaultConfig.versionName` / `versionCode`；
4. 找不到环境文件时**回退 pubspec.yaml**（`flutter.versionCode/versionName`，当前 `3.0.0+300`）；
5. 通过 `applicationVariants.configureEach { outputs.all { outputFileName = ... } }`（对齐原生 Android 写法）把 **release 与 debug** 产物重命名为 `<APP_NAME>-<APP_VERSION>-<APP_BUILD>-<BUILD_TYPE>.apk`（前缀取 `.env` 的 `APP_NAME`，缺失/为空时回退 `fastapiadmin`；同 applicationId 靠后缀区分，如 dev `FastapiAdmin-3.0.0-alpha-301-release.apk` / `FastapiAdmin-3.0.0-alpha-301-debug.apk`，prod `FastapiAdmin-3.0.0-300-release.apk`）。

因此**版本号改动只改 `.env` 文件**，`pubspec.yaml` 的 `version` 仅作为兜底，二者不同步时以 `.env` 为准（Dart 侧 `AppEnv.appVersion` 与 Android 侧 versionName 读同一份 `.env`，天然一致）。
产物文件名由 `APP_NAME`、`APP_VERSION`、`APP_BUILD` 原顺序拼接、末尾追加构建类型后缀自动派生（`<APP_NAME>-<APP_VERSION>-<APP_BUILD>-<BUILD_TYPE>.apk`），无需单独配置。

### iOS 产物命名（Makefile 派生）

`make build-ios` 构建后会把 `build/ios/iphoneos/Runner.app` 用 `ditto` 复制一份并命名为 `<APP_NAME>-<APP_VERSION>-<APP_BUILD>.app`（对齐 Android 命名，如 dev `FastapiAdmin-3.0.0-alpha-301.app`、prod `FastapiAdmin-3.0.0-300.app`）；`Runner.app` 原样保留，供 `flutter install` 等工具使用。同样由 `.env` 的 `APP_NAME` / `APP_VERSION` / `APP_BUILD` 派生，无需单独配置。

`make build-ipa`（**默认 ENV=prod**，分发包）生成 `<APP_NAME>-<APP_VERSION>-<APP_BUILD>.ipa`（如 `FastapiAdmin-3.0.0-300.ipa`），并自动用 `--build-name/--build-number` 把 ipa 内部版本号覆盖为 `.env` 值——iOS 不走 gradle，不覆盖会取 pubspec `3.0.0+300`，导致 dev 包误标 prod 版本。`--build-name` 取**剥离 `-alpha`/`-rc` 后缀的数字版本**（iOS 仅接受 `x.y.z`，如 dev `3.0.0-alpha` → 内部 `3.0.0`），文件名仍保留完整 `APP_VERSION`（`FastapiAdmin-3.0.0-alpha-301.ipa`）；`--build-number` 用 `APP_BUILD`（dev 301 > prod 300，可覆盖安装）。导出方式默认 `development`（本机仅 Apple Development 证书，一键可出包）；`EXPORT_METHOD=app-store` 可切 TestFlight/上架导出（需 App Store 分发证书）。

## 三、当前版本方案

| 环境   | `APP_VERSION` | `APP_BUILD` | 能否覆盖安装 prod |
| ------ | ------------- | ----------- | ----------------- |
| `prod` | `3.0.0`       | `300`       | —（基准）         |
| `dev`  | `3.0.0-alpha` | `301`       | ✅（301 > 300）   |
| `test` | `3.0.0-rc`    | `302`       | ✅（302 > 300）   |

> 原则：预发布包的 `APP_BUILD` 应保持递增（prod < dev < test < 下一个 prod），确保可从低版本向高版本覆盖安装。

## 四、构建命令

```bash
# 构建 dev release 测试包（版本与产物名由 gradle 从 .env.dev 自动派生）
make build-android-dev
# → 产物：build/app/outputs/apk/release/FastapiAdmin-3.0.0-alpha-301-release.apk

# 构建 prod release 包（版本自动取 .env.prod）
make build-android
# → 产物：build/app/outputs/apk/release/FastapiAdmin-3.0.0-300-release.apk（以及 flutter-apk/app-release.apk）

# 构建 iOS dev 测试包（产物名由 .env.dev 派生，Runner.app 副本）
make build-ios
# → 产物：build/ios/iphoneos/FastapiAdmin-3.0.0-alpha-301.app（Runner.app 原样保留供 flutter install）

# 构建 iOS 生产包
make build-ios ENV=prod
# → 产物：build/ios/iphoneos/FastapiAdmin-3.0.0-300.app

# 构建 iOS 分发包（默认 ENV=prod，产物名与版本号由 .env.prod 派生，development 导出）
make build-ipa
# → 产物：build/ios/ipa/FastapiAdmin-3.0.0-300.ipa（含 Payload/Runner.app；EXPORT_METHOD=app-store 可切上架导出）

# 构建 iOS dev 分发包
make build-ipa ENV=dev
# → 产物：build/ios/ipa/FastapiAdmin-3.0.0-alpha-301.ipa

# 一键打包：Android prod APK + iOS prod ipa，一条命令出全部
make package
# → build/app/outputs/apk/release/FastapiAdmin-3.0.0-300-release.apk
# + build/ios/ipa/FastapiAdmin-3.0.0-300.ipa

# 一键打包 dev 测试包
make package-dev
# → FastapiAdmin-3.0.0-alpha-301-release.apk + FastapiAdmin-3.0.0-alpha-301.ipa

# 任意环境：直接指定 ENV
flutter build apk --release --dart-define=ENV=test
```

- **Gradle 命名产物**：`build/app/outputs/apk/release/` 与 `apk/debug/`（原生 Android 的 gradle 输出目录）；dev release 为 `FastapiAdmin-3.0.0-alpha-301-release.apk`、debug 为 `FastapiAdmin-3.0.0-alpha-301-debug.apk`，prod release 为 `FastapiAdmin-3.0.0-300-release.apk`。
- **Flutter 规范产物**：`build/app/outputs/flutter-apk/app-release.apk` / `app-debug.apk`（Flutter 插件固定名，供 `flutter install` 等工具使用）。
- 重命名对 `release` 与 `debug` 两个变体均生效（同包名 `com.fastapiadmin.fastapiadmin_mobile`，靠文件名后缀区分，避免混淆）。
- **iOS 产物**：`make build-ipa` 生成 `build/ios/ipa/<APP_NAME>-<APP_VERSION>-<APP_BUILD>.ipa`（如 `FastapiAdmin-3.0.0-300.ipa`），版本号由 `.env` 派生。

运行（debug）同理，`make run-dev` 即 `flutter run --dart-define=ENV=dev`。

## 五、注意事项

1. **`--build-name / --build-number` 对 Android 已失效**：Android 版本号以 `.env` 为准，命令行版本参数被忽略。要改版本请直接编辑对应 `.env` 文件。
2. **改版本后需同步语义**：`APP_VERSION` 同时被 Dart 侧 `AppEnv.appVersion` 读取，用于「我的 → 关于 → 版本号」toast 展示，改它等于同时改 APK versionName 与 App 内展示版本；产物文件名也随 `APP_VERSION`/`APP_BUILD` 自动派生，无需另改。
3. **签名**：release / debug 均用 `android/key.properties` 指向的 keystore 签名（`signingConfigs.release`），更换 `APP_BUILD` 不影响签名。
4. **CI / 自动发版**：如需在 CI 里动态设置版本号，不要用 `--build-*`，改为在构建前写入对应 `.env` 文件，或临时使用 `sed`/脚本替换 `APP_VERSION` / `APP_BUILD`。
